A. PENDAHULUAN

Named Routes merupakan mekanisme navigasi pada Flutter yang menggunakan nama string untuk mengidentifikasi dan mengakses halaman aplikasi secara terpusat melalui properti routes pada MaterialApp. Selain itu, BottomNavigationBar digunakan sebagai antarmuka menu di bagian bawah layar untuk memudahkan perpindahan antar halaman utama (Dashboard, Riwayat, dan Profil) di dalam satu Scaffold. Pada laporan ini, aplikasi juga diintegrasikan dengan Local Storage menggunakan SQLite untuk memastikan data akun (Login/Register) dan riwayat transaksi tersimpan secara persisten.

B. TUJUAN PRAKTIKUM

  • Menerapkan Named Routes untuk mengatur navigasi antarhalaman secara terstruktur tanpa spaghetti code.
  • Mengimplementasikan BottomNavigationBar sebagai menu navigasi bawah yang interaktif.
  • Mengintegrasikan halaman Dashboard, Riwayat, dan Profil dalam satu struktur navigasi.
  • Menggabungkan materi praktikum 1-5 menjadi satu project utuh yang dilengkapi basis data lokal (SQLite).

C. LANGKAH KERJA (NAVIGASI DASAR)

1. Mendaftarkan Named Routes

Menghapus parameter home pada MaterialApp di file main.dart dan menggantinya dengan initialRoute serta routes. Rute '/' diarahkan untuk memuat antarmuka Login, sedangkan rute lainnya disiapkan untuk navigasi layar utama dan form penambahan transaksi.

2. Merangkai Penampung Tab (Main Screen)

Membuat StatefulWidget pada main_screen.dart untuk menampung properti BottomNavigationBar. Layar ini menggunakan variabel _selectedIndex untuk mendeteksi indeks tab yang sedang aktif, lalu memuat halaman dari List _pages secara dinamis.

D. PENYELESAIAN TUGAS (INTEGRASI & SQLITE)

1. Menggabungkan Hasil Praktikum 1-5

Seluruh antarmuka dari Modul 1 hingga 4 (Widget, Layout, Form, Validasi, dan Navigasi Passing Data) digabungkan menjadi satu project. Tampilan UI/UX dasar tetap dipertahankan, dengan tambahan logika dinamis untuk menampilkan data dari database.

2. Menambahkan Local Storage (SQLite)

Mengonfigurasi paket sqflite dan path di dalam pubspec.yaml. Pembuatan tabel dieksekusi melalui kelas DatabaseHelper dengan menerapkan pola Singleton, sehingga koneksi ke database hanya dibuka satu kali selama aplikasi berjalan. Dua tabel utama dibuat: tabel users untuk otentikasi dan tabel transactions untuk riwayat keuangan.

3. Pembuatan Form Login & Register

Membangun antarmuka baru untuk mendaftarkan pengguna dan memverifikasi sesi login. Proses registrasi menangkap input nama, email, dan password yang langsung dimasukkan ke SQLite. Validasi form diimplementasikan untuk memastikan format email benar dan input tidak dibiarkan kosong.

4. Pengolahan Data Transaksi (CRUD)

Mengubah statis UI pada halaman Riwayat dan Dashboard menggunakan FutureBuilder. Komponen ini secara asinkron akan memanggil fungsi getTransactions(userEmail) dari DatabaseHelper dan mencetak daftarnya ke layar. Penyimpanan data transaksi baru dilakukan melalui form yang memicu fungsi insertTransaction().

5. Generate File APK

Setelah seluruh fungsionalitas dan navigasi diuji coba, aplikasi dikompilasi menjadi format siap instal. Proses kompilasi dilakukan melalui terminal menggunakan perintah flutter build apk --release untuk menghasilkan file app-release.apk.

E. KESIMPULAN

Melalui praktikum ini, fungsionalitas aplikasi Expense Tracker berhasil disempurnakan. Penggunaan arsitektur Named Routes dan BottomNavigationBar terbukti membuat pengelolaan perpindahan antar layar menjadi jauh lebih rapi dan terpusat. Selain itu, implementasi SQLite sukses menyelesaikan kelemahan data statis pada modul sebelumnya. Aplikasi kini mampu menyimpan identitas pendaftar serta membedakan pencatatan riwayat transaksi milik pengguna secara persisten meskipun aplikasi ditutup sepenuhnya.
